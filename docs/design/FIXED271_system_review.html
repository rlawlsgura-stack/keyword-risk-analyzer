FastAPI가 중단되어도 화면의 기본 기능은 독립적으로 실행할 수 있습니다. Supabase 장애는 두 서버의 로그인·조회·저장에 영향을 줄 수 있습니다.

2. 로그인부터 기록 저장까지

① 로그인Supabase Auth에 계정 확인 요청
② 역할 확인admin/member 허용
그 외 앱 접근 차단
③ 입력·실행텍스트와 매칭 옵션 선택
④ 최신 데이터 읽기키워드·공통 설정 조회
카테고리·등급 필터
⑤ Python 매칭등록 표현과 원문 비교
검출 위치 계산
⑥ 기록 후 표시검출 시 DB 기록·집계
표·하이라이트·CSV 표시

검출 결과가 있으면 분석 기록, 검출 이벤트, 조회수를 DB에서 한 번에 저장합니다. 저장이 성공한 뒤 화면 표시용 결과를 설정하므로 저장 장애가 결과 표시에 영향을 줄 수 있습니다. 미검출이면 현재 UI는 분석 기록을 저장하지 않습니다.

로그인 세션

로그인 정보는 사용자별 Streamlit session_state에 보관합니다. 만료가 가까우면 토큰을 갱신하고 화면 재실행 때 사용자·역할을 다시 확인합니다. “로그인 세션을 확인할 수 없습니다”는 토큰 확인·갱신 실패와 통신 장애를 함께 나타낼 수 있습니다. 과부하 시 자동 로그아웃하는 별도 기능으로 구현된 것은 아닙니다. 브라우저 연결·서버 재시작으로 세션이 사라지는 경우는 별도입니다.

조회수의 의미

한 번의 분석에서 같은 키워드가 5번 등장해도 해당 키워드는 1회 집계됩니다. 분석 버튼을 다시 눌러 새 분석을 실행하면 다시 집계됩니다. API는 기본적으로 record=false이므로 기록을 명시적으로 요청해야 합니다.

인증은 Authorization: Bearer …에 Supabase 사용자 access token 또는 별도 API_ACCESS_TOKEN을 전달합니다. 사용자 토큰은 Auth 서버에서 역할을 확인합니다. 공통 연동 토큰은 모두 같은 integration 주체로 처리됩니다. Supabase 서버 비밀 키를 API 호출자에게 전달하지 않습니다.

키워드 편집·조회수 초기화·사용자 역할 변경 API는 없습니다. Streamlit 관리자 화면에서 직접 수행합니다. API_DOCS_ENABLED는 문서 UI 표시 설정이며, API 자체의 인증을 대신하지 않습니다.

4. DB 운영과 접근 권한

아래는 저장소 SQL의 구현 기준입니다. 실제 운영 DB와 동일한지는 미확인입니다.

테이블내용관계·용도
kra_keywords키워드 원장·누적 조회수·마지막 검출 시각kwd_no로 식별
kra_settings공통 기호·접미사·선택 목록설정 이름으로 조회
kra_state원장 버전과 컬럼 정보동시 편집 충돌 검사
kra_runs분석 ID·실행 주체·입력 식별값·결과분석 1회 단위
kra_hits분석별 키워드·검출 시각·표시 여부analysis_id → kra_runs

광고 원문 전체를 별도 필드로 저장하지 않습니다. 결과에는 등록 키워드 정보와 검출 위치 등이 포함됩니다. 검출 로그의 키워드 번호에는 원장 외래키가 없어 키워드 삭제 후에도 기록이 남습니다. 삭제한 번호를 다른 의미로 재사용하면 과거 통계 해석이 혼동될 수 있습니다.

권한과 데이터 변경

SQL은 일반 클라이언트의 직접 접근을 막고 서버 역할의 접근을 허용합니다. 실제 DB 통신은 서버 비밀 키로 수행하므로 사용자별 접근 경계는 Python 권한 검사와 분석 소유자 검사입니다. RLS 활성화만으로 모든 사용자 권한을 자동 보호하는 구조는 아닙니다.

  • 원장 수정 시 버전 번호를 검사해 오래된 데이터의 덮어쓰기를 거절합니다.
  • 원장 저장은 전체 목록 기준으로 반영하므로 빠진 키워드는 삭제될 수 있습니다.
  • 분석 기록·검출 이벤트·조회수는 하나의 트랜잭션으로 처리합니다.
  • 같은 API 분석 ID 재시도는 중복 집계를 방지합니다.
초기화 종류변경유지
전체 조회수누적 0, 마지막 검출 시각 비움분석·검출 기록
최근 7일최근 이벤트를 리포트에서 제외누적 조회수·원본 이벤트

전체 조회수 초기화 뒤 주간 리포트가 남는 것은 현재 설계상 정상입니다.

백업

CSV 다운로드는 원장 내보내기이며 전체 DB 백업이 아닙니다. 자동 백업·정기 복원 검증은 앱 코드에 없습니다. Supabase 백업 제공 범위와 보존 기간은 실제 프로젝트 요금제·설정을 확인해야 합니다. Supabase 백업 공식 문서

5. Kiwi·임베딩 보조 분석

기본 분석과 별도 버튼으로 실행합니다. 결과는 검토 후보이며 기본 표·하이라이트·CSV·조회수에 반영하지 않습니다.

항목Kiwi임베딩
목적형태가 변한 표현의 관련 후보 탐색의미가 가까운 등록 키워드 탐색
실행 위치Streamlit 또는 FastAPI 서버 내부외부 API로 벡터 생성, 해당 서버에서 비교
외부 전송없음입력 문구·선택 원장의 키워드·카테고리·심의기준
보관서버 메모리 캐시서버 메모리 캐시. 영구 벡터 DB 없음
예시개선하다 ↔ 개선했어요 같은 형태 비교글자가 달라도 의미가 가까운 표현을 후보로 제시
  • Kiwi는 의미 점수 순위가 아니라 원장 순서에 따라 제한된 후보를 반환합니다.
  • 임베딩은 최소 유사도 기준이 없어 관련성이 약한 후보도 나올 수 있습니다.
  • 두 기능을 모두 선택하면 현재는 순차 실행합니다.
  • 벡터 캐시는 서버 재시작 후 없어질 수 있어 다시 생성 비용이 발생할 수 있습니다.
  • 예상된 모델·통신 오류는 해당 보조 기능에 표시하고 기존 문자 분석 결과는 유지합니다.
법령 RAG와 구분해야 합니다.
현재 검색 대상은 등록 키워드 원장입니다. 법령 원문 검색, 조항 인용, 위반 판정, LLM 설명 생성은 연결되지 않았습니다. 문서상 외부 호출은 429로 완료되지 못한 이력이 있습니다. 현재 잔액·호출 성공·실제 검색 품질은 미확인입니다.

현재 render.yaml은 UI와 API를 모두 Render에 생성하는 설정입니다. Community Cloud 화면을 유지한다면 Render UI는 중복 구성입니다. 실제 서비스 생성·가동 여부는 미확인입니다.

로컬 실행

# 화면
.\.venv\Scripts\python.exe -m streamlit run keyword_app2_fixed271.py

# 별도 API
.\.venv\Scripts\python.exe -m uvicorn api:app --host 127.0.0.1 --port 8000
설정 이름역할
STORAGE_BACKEND운영은 supabase. 누락하면 csv 기본값
SUPABASE_URL연결할 프로젝트 주소

공통 설정 로더는 프로세스 환경변수 → 로컬 .env → Streamlit Secrets 순서로 없는 값만 채웁니다. 중복된 빈 값도 뒤 설정을 막을 수 있습니다. Render 설정과 Secrets 예제에는 임베딩 관련 값이 없어 사용 환경에 별도 설정해야 합니다.

권장 배포·롤백 절차

  1. 검증한 수정본을 Git 커밋과 버전 태그로 고정합니다.
  2. 배포 환경 실행 파일이 fixed271인지 확인합니다.
  3. DB 변경 시 백업과 SQL 변경 이력을 준비합니다.
  4. 배포 후 로그인·역할·분석·집계·보조 오류 처리를 점검합니다.
  5. 문제 발생 시 이전 Git 커밋 전체로 되돌립니다. DB 변경은 별도 복구 판단이 필요합니다.

fixed270.py만 실행하는 것은 전체 롤백이 아닙니다. 두 화면은 공통 분석·저장소 모듈을 공유합니다.

8. 개선 우선순위

우선순위개선 작업이유
최우선노출된 실제 자격 증명 교체 여부 확인서버 키의 DB·계정 관리 권한 보호
높음운영에서 Supabase 모드 필수화설정 누락 시 CSV 모드로 시작해 공용 로그인 절차를 거치지 않음. 관리자 편집은 별도 인증 필요
높음FIXED271 커밋·태그와 배포 버전 확인로컬과 운영의 차이를 추적하고 전체 롤백 기준 확보
높음백업·복원 절차 확정CSV만으로 전체 DB·계정·기록 복구 불가
높음로그인 오류 구분·운영 로그통신 장애와 토큰 문제를 구분해 대응
높음사용자 화면의 전체 오류 추적 출력 제거현재 분석 오류 시 내부 파일·호출 구조가 노출될 수 있음
중간임베딩 호출 제한·예산·품질 기준호출 비용과 관련성이 약한 후보 관리
중간연동처별 API 토큰·소유자 분리현재 공통 토큰 사용자는 같은 integration 주체로 처리
중간화면·API 조건 계약 정리이름이 비슷한 모드의 결과 차이 방지
중간실제 동시 사용자 부하 검증DB 쓰기 잠금·Kiwi 직렬 처리·전체 원장 조회 영향 확인
중간관리자 변경 감사·보존 기간원장·역할 변경 추적과 데이터 증가 관리

먼저 배포 버전 고정, 인증 장애 진단, 백업, 분석 조건 일치를 정리하는 것이 사내 운영 안정성에 가장 직접적입니다.
