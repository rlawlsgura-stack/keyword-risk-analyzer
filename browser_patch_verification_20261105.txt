브라우저 패치 적용 검증 결과 (2026-11-05, 한국 시간)

대상
- React: http://localhost:5173/
- 로그인 상태: 기존 로컬 관리자 계정
- 원장 표시: 0개, 버전 6
- 사용자 PC의 frontend/QA_STATUS.md는 이번 세션에서 직접 수정하지 않음.
- 아래 결과는 사용자 보고와 구분되는 실제 브라우저 관찰 결과임.

확인 완료
1. 브라우저 탭 제어 및 실제 React 화면 읽기 성공.
2. 스크립트 분석 화면에 리스트 필터 영역이 표시됨.
   - 번호/키워드명/대체 키워드 검색창
   - 카테고리, 리스크, 증빙 유형 필터
   - 필터 적용, 필터 초기화
   - 필터 결과 CSV 다운로드, 전체 원장 CSV
3. 리스트 검색창에 '안티에이징'을 입력하고 적용:
   - 오류 알림 없이 '0개 키워드', '조건에 맞는 키워드가 없습니다.' 표시.
4. 검색어 입력 후 필터 초기화:
   - 검색창의 실제 DOM value가 빈 문자열로 돌아오는 것을 확인.
   - 3개 분류 필터는 전체 값으로 표시됨.
   - 단, 원장이 비어 있어 분류 선택값을 변경했다가 초기화하는 검사는 불가능.
5. 키워드 문의내역 → 대상 키워드 검색:
   - '안티에이징' 검색 후 이전 Failed to fetch 알림이 나타나지 않음.
   - 검색 결과 항목 없음. 검색 전용 0건 안내는 확인되지 않음.
   - 실제 문의 작성·등록·답변은 미검증.
6. 키워드 관리 → 정규화 설정:
   - 기본 기호 / & , *가 /&,* 형태로 표시됨.
   - 추가 허용 조사·어미 입력은 빈 상태, 기본 허용 목록 55개 안내 표시.
   - '저장된 값 다시 불러오기'를 누른 뒤 오류 알림 없음.
   - 설정 저장은 실행하지 않음.

미검증
- 필터 결과 CSV: 버튼을 클릭했지만 다운로드 이벤트 대기 5초 내 파일을 확보하지 못함.
  앱의 다운로드 실패로 확정할 수 없음. 실제 다운로드 파일·인코딩·Excel 표시는 미검증.
- 원장 0건으로 실제 카테고리/리스크/증빙 선택 결과와 검출 정확도 비교 불가.
- 동일 데이터의 React/Streamlit 분석 결과, OCR 후보 편집/저장, 문의 처리,
  데이터가 있는 리포트, 일반 사용자 권한과 나머지 58개 항목의 동등성은 미완료.
- 초기 확인 도중 브라우저 작업 응답 지연으로 연결을 재초기화했으며,
  그 뒤 초기화와 설정 조회를 다시 직접 확인함.

변경 범위
- 화면 이동, 검색, 입력값 초기화, 설정 재조회 및 CSV 다운로드 클릭만 수행.
- 분석 실행, 키워드 추가/수정/삭제, 규칙 저장, 계정 권한 변경,
  문의 제출, 코드 수정, 커밋·푸시·배포는 하지 않음.

후속 확인
- 실제 CSV 파일을 확보해 헤더·UTF-8 BOM·행 수를 확인.
- 로컬 비교용 키워드가 준비되면 같은 옵션·문장으로 매칭 모드별 결과 비교.
- 기존 58개 항목 중 미검증과 미구현 UI 차이는 계속 별도로 관리.
