## 목적과 기준 고정

React 운영 화면 전환 시 기능·매칭 결과·저장 데이터·화면 표시를 Streamlit FIXED327과 대조하기 위한 기준이다. 기준 소스는 커밋 `81989506772aa164cdf510747a4f962093ece845`의 `keyword_app2_fixed327.py`이며, 전체 기준은 다음 명령으로 재현한다.

```powershell
git show 81989506772aa164cdf510747a4f962093ece845:keyword_app2_fixed327.py
```

327 기준 앱 버전 문자열은 `FIXED327`이다. 화면의 정확한 글꼴 렌더링은 OS와 브라우저에 따라 달라질 수 있으므로, 전환 검수는 같은 브라우저·뷰포트·데이터에서 글꼴군, 크기, 굵기, 색, 간격, 줄바꿈, 위젯 배치와 동작을 비교한다. Streamlit 기본 테마와 위젯을 그대로 React의 기본 스타일로 간주하지 않는다.

## 배포 구조와 선행 설계 판단

현재 `render.yaml`은 Streamlit 웹 서비스, FastAPI 웹 서비스, React 정적 사이트를 각각 정의한다. React는 FastAPI를 호출하고 Streamlit과 FastAPI는 같은 Supabase 프로젝트와 저장소 구현을 사용한다. 따라서 API 계층을 없애는 전환이 아니라 기존 Streamlit 동작을 HTTP 계약으로 보존하는 전환이다.

API를 새로 설계하거나 DB를 이관해야만 시작할 구조적 선행 조건은 확인되지 않았다. 다만 현재 API에는 레거시 `/api/v1/analyses`와 현재 규칙용 `/api/v2/analyses`가 공존하고, React 분석은 `record_analysis_with_unmatched` RPC로 결과와 미매칭 수집을 한 트랜잭션에 기록한다. FIXED327은 분석 기록과 미매칭 수집을 별도 처리한다. 이 차이는 장애·재시도 때 영속 결과가 달라질 수 있으므로 동등성 결정이 필요한 선행 설계 항목이다.

API 설계 문서 `02_api_design.md`와 화면·DB 설계 문서 중 일부는 더 오래된 앱 버전을 설명한다. 이 문서는 FIXED327을 기준으로 하는 React 전환 검수 명세이며, 기존 설계서를 FIXED327의 사실로 간주하지 않는다. 전환 구현에 들어가기 전에 API 계약을 이 명세의 데이터·실패 의미에 맞춰 갱신하고, 기존 클라이언트 호환 정책을 명시한다.

API 계약에서 갱신한 응답 확장은 다음과 같다.

## 분석 입력·매칭 기준

입력 원문은 최대 20,000자이며 기본 예시 문장이 설정된다. 분석 전 사전 필터(expander, 기본 열림)에서 상품카테고리·리스크 등급을 다중 선택하고, 세 가지 매칭 방식 중 하나를 선택한다.

| 옵션 | FIXED327 의미 | 검수 |
|---|---|---|
| 키워드 완전 일치 | 문장 안에서 등록 표현 검색. 단어 경계 강제 없음 | 등록 키워드, 옵션 조합별 검출·범위 |
| 키워드 일부 일치 | Kiwi 내용어 토큰 비교 및 관리자 승인 표현 보완 | 승인 표현, 경계, 다중 토큰 사례 |
| 글자 수 매칭 - 탐색용 | 부분 문자열. 최소 2–20자 설정 | 경계·임계값 직전/직후 사례 |
| 등록 키워드 괄호 설명 제외 | 등록명에서 괄호 설명을 제거해 비교 | 원문 괄호는 보존되는지 |
| 띄어쓰기·줄바꿈 차이 허용 | 비교 시 공백 차이 정규화 | 원문 표시 및 매칭 범위 |
| 영문 대소문자 무시 | 영문 대소문자 정규화 | 혼합 대소문자 |
| 설정된 기호를 공백 처리 | 공통 기호 설정 적용 | 기호 켬/끔, 관리자 목록 |

매칭 설정은 분석 실행 시 DB의 최신 공통 설정을 불러온다. React는 입력·필터·모드·최소 글자 수·정규화 옵션을 동일한 값과 기본값으로 전송해야 하며, 조회 시점·권한·설정 revision을 결과에서 추적할 수 있어야 한다. 매칭 본문은 `approved_matching.py`/`matching_engine.py`를 기준으로 하며, 화면 표시용 범위 병합과 개별 매칭 레코드 보존을 혼동하지 않는다.

## 결과·미리보기·CSV

FIXED327은 고유 검출 키워드 수를 성공 메시지로 표시한다. 결과 표는 매칭 occurrence 목록이 아니라 검출된 고유 `kwd_no`를 DB 원장과 결합하고 코드 오름차순으로 정렬한다. 화면 표에는 원장의 전체 열을 표시하고, 긴 심의기준은 Streamlit 표 동작을 따른다.

미리보기는 원문 보존, 리스크별 하이라이트, `【검출문구】` 장식, 연결 키워드 번호를 표시한다. 번호는 마우스 오버 툴팁이 아니라 클릭 상세 팝업이며, 번호의 Ctrl+클릭 선택과 복사 동작을 지원한다. 겹치는 시각 구간은 병합할 수 있지만 원래 검출 키워드와 번호는 누락·중복 없이 유지한다. 상세 표는 원장 행 전체에 조회·등록일과 해당 occurrence의 매칭 결과·조건을 더한 값이다.

분석 결과 CSV(`analysis_results.csv`)는 고유 키워드 표가 아니라 occurrence 행을 내보낸다. 열 순서는 `kwd_no`, `키워드명`, `상품카테고리`, `리스크 등급`, `리스크 등급별 세부 심의기준`, `start`, `end`이다. UTF-8-SIG 인코딩, 날짜/오프셋 형식, 한글, 쉼표·개행과 셀 값을 검수한다. 현재 React CSV 생성기는 `=`, `+`, `-`, `@`로 시작하는 값을 작은따옴표로 접두 처리하지만 327의 pandas CSV는 이를 하지 않아 파일 값이 다를 수 있다. 전환 명세에서는 값 보존 여부와 스프레드시트 수식 방어 정책을 별도 결정하고, 승인된 정책을 결과·리포트·원장 CSV에 일관 적용한다.

## 분석 저장 및 조회수 규칙

성공한 분석은 각 고유 키워드의 누적 조회수를 한 번 증가시키고 마지막 검색일자를 갱신하며, 해당 occurrence와 분석 결과를 로그에 기록한다. 미매칭 표현은 자동 수집하며 원문·이미지·계정 정보를 후보 통계에 저장하지 않는다. 카테고리·리스크 필터가 설정되어도 미매칭 통계 범위가 필터 결과로 잘못 축소되지 않는지 확인한다.

동일 요청 재전송, 네트워크 단절, 저장 일부 실패, 최신 원장 revision 변경 시 Streamlit 기준의 카운터·로그·후보 수집 결과와 React 결과를 비교한다. 현재 React의 단일 원자 RPC는 부분 성공을 방지하지만 FIXED327의 별도 저장 흐름과 실패 의미가 다르다. 제품 동작으로 원자성을 채택할지, 327 동작을 재현할지 결정하고 이를 API 계약·운영 안내에 명시하기 전에는 저장 동등성 완료로 표시하지 않는다.

## 리포트·초기화 기준

리포트 기본 기간은 한국 시간 오늘을 포함한 최근 7일(오늘-6일~오늘), 기본 Top N은 10이며 1–100 범위를 허용한다. 로그 timestamp에서 기간 내 발생 수를 집계해 내림차순으로 Top N을 선정한다. 결과를 전체 키워드 원장과 결합하고 검색 순위, 원장 컬럼 전체, 기간 내 조회수를 표시한다. 동률 선정과 표시 순서는 기존 Pandas 처리 순서까지 같은 데이터로 대조한다.

리포트 CSV(`period_topN_report.csv`)는 화면 리포트 전체 컬럼을 같은 순서로 내보낸다. 관리자 초기화는 확인 체크박스와 별도 실행 버튼을 요구한다. 전체 초기화는 원장 누적 카운터를 0, 마지막 검색일자를 공백으로 하고 로그를 보존한다. 최근 7일 초기화는 최근 로그를 리포트에서 제외하고 누적 카운터는 건드리지 않는다. DB 응답, 확인 취소, 오류, 재실행에서도 같은 결과를 검수한다.

## 데이터 기준

원장 기준 컬럼은 `matching_engine.DB_COLS` 및 FIXED327의 동적 컬럼 순서다: `kwd_no`, `키워드명`, `상품카테고리`, `리스크 등급`, `대체키워드`, `리스크 등급별 세부 심의기준`, `증빙자료유형`, `키워드 조회 수(누적카운트)`, `마지막 출력일자`. 사용자 화면에서는 마지막 출력일자를 마지막 검색일자로 표시하고, 심의 기준 긴 텍스트는 전체 내용을 확인할 수 있어야 한다. 운영 DB는 Supabase `kra_` 저장소이며 React가 브라우저에서 service-role 키를 사용하지 않는다.

데이터 동등성 검수는 같은 DB revision·같은 계정 역할·같은 설정으로 수행한다. 원장 전체 열과 tooltip, 날짜 표기, 빈 값·`-`·0 표현, 정렬, CSV 열 이름과 순서를 대조한다. API 응답에서 화면 필드만 반환해 원장 값을 잃지 않는지 확인한다.

| 분석 CSV | 327의 occurrence 7열, 파일명, UTF-8 BOM 헤더 반영 | React formula-leading 값 접두 처리 때문에 값 차이는 유지 | 승인된 CSV 수식 방어 정책 및 셀 단위 비교 |
| 저장 | React `/api/v2/analyses`, 원자 RPC | 327 기록과 후보 수집은 분리 처리 | 원자성 정책 결정, 재시도·부분 실패 비교 |
| 리포트 | API 기간 조회 응답에 전체 원장 행·revision·순위 추가, 화면/CSV 전체 열 반영 | 실제 화면과 CSV 파일 비교, 초기화 확인 UX 차이 남음 | 같은 기간 결과·모든 열·파일·초기화 비교 |
| 일반 사용자/관리자 | 각 기능 대응 페이지와 API가 존재 | QA 기록상 인증 UI 검증 미완료 영역 다수 | 역할별 기능 행렬 전수 검증 |
| OCR | API 배포와 업로드 UI 존재 | 인증 사용자 OCR 추론 미검증 | 한국어 실제 이미지 인식·후보 저장 검증 |

`frontend/QA_STATUS.md` 기준으로 빌드·배포와 일부 인증 분석은 확인되었지만, 리포트 화면/CSV, OCR 추론, 카탈로그·규정 검색·후보·문의·사용자/키워드 관리 등 다수 화면의 인증 검증, 전체 parity review는 완료되지 않았다. 브라우저 자동화 호스트 문제가 기록되어 있어 현재 문서 검토는 소스와 QA 기록 기준이며, live 화면의 완전 일치는 주장하지 않는다.

## 완료 판정과 검수 기록

각 검수 행은 Streamlit 327과 React에서 같은 테스트 계정 역할, 동일 입력·DB revision·설정·기간으로 실행하고 다음을 보관한다: 화면 캡처, 실제 요청/응답(비밀값 제거), CSV 파일, 저장 전후 DB 지표, 결과 판정과 이슈 링크. 일반 사용자와 관리자 역할을 각각 검수한다.

모든 화면·동작·값·권한·저장·CSV 항목이 통과하고, 실패·재시도 차이가 승인된 계약과 일치한 뒤에만 “운영 UI 전환 가능”으로 판정한다. FIXED327 기준 검증이 끝날 때까지 Streamlit을 운영 UI로 유지한다.
