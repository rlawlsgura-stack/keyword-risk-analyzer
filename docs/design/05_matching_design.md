# Keyword Risk Analyzer 분석 로직 설계서

문서 ID KRA ENG 001 · 버전 1.3 · 기준일 2026년 10월 22일

## 엔진 경계

`matching_engine.py`는 Streamlit, Auth와 파일 저장을 사용하지 않는 규칙 기반 엔진입니다. 입력 원문과 pandas DataFrame, 명시적 설정을 받아 Match2 목록을 반환합니다. 조회수 증가와 원장 저장은 엔진 밖에서 수행합니다. NLP라는 함수 이름이 있지만 외부 언어 모델이나 형태소 분석 서버를 호출하지 않습니다.

## 입력 자료형

| 입력 | 형식 | 설명 |
|---|---|---|
| text | string | 원문, 표시 위치의 기준 |
| kw_df | pandas DataFrame | kwd_no와 키워드 속성 |
| match_mode | string | 정확 일치, 유사 키워드 포함, 부분 문자열 |
| exact_relaxed | boolean | 기존 묶음 옵션 호환용. 신규 UI는 개별 옵션 사용 |
| strip_bracket_notes | boolean 또는 null | 등록명에서 괄호 설명을 제외한 후보 허용 |
| normalize_whitespace | boolean 또는 null | 공백·줄바꿈·일부 보이지 않는 공백을 제외하고 비교 |
| ignore_case | boolean 또는 null | 영문 대소문자를 구분하지 않고 비교 |
| normalize_symbols | boolean 또는 null | 공통 목록의 기호를 공백으로 치환 |
| config | MatchingConfig | 무시 기호와 허용 조사 어미 |
| partial_min_len | integer | 부분 문자열의 최소 길이 |
| similar_reverse_single | boolean | 한 토큰 입력의 키워드 역매칭 |
| similar_reverse_any | boolean | 다중 입력 토큰의 역매칭 |

MatchingConfig는 변경 불가 dataclass입니다. 기본 무시 기호는 `/`, `&`, `,`, `*`이며 기본 한국어 조사 어미 목록을 포함합니다. 독립 엔진 호출자는 빈 tuple 또는 frozenset을 전달해 기본 규칙을 비활성화할 수 있습니다. 앱과 API 어댑터는 빈 무시 기호 목록을 기본값으로 되돌리는 기존 동작을 유지합니다.

설정 스냅샷에는 mode(exact/similar/partial), exact_relaxed, partial_min_len,
similar_reverse_single, similar_reverse_any, exact_fallback_similar와 exact_fallback_min_tokens도 포함합니다.
UI와 API는 이 객체 하나로 엔진을 호출합니다. 기존 match_mode 등 개별 인수는
호환 어댑터인 _resolve_config에서 스냅샷으로 변환하며 명시한 인수가 우선합니다.

화면은 완전 일치, 일부 일치, 글자 수 매칭 - 탐색용 세 가지입니다. 완전 일치는 exact 엔진, 일부 일치는 partial 엔진과 최소 2글자, 글자 수 매칭은 partial 엔진과 사용자 지정 최소 길이를 사용합니다. 따라서 글자 수 매칭을 2로 설정하면 일부 일치와 결과가 같습니다. 기존 similar 엔진과 두 역매칭 옵션은 API 호환 경로에만 남깁니다. 화면의 similar 선택값은 partial+2로 변환하며 API의 similar와 구별합니다. 선택 영역 제목은 키워드 매칭 방식이며 네 개별 옵션은 키워드 매칭 옵션 익스팬더에 배치합니다.
표시 이름은 mode ID와 분리되어 있으며 기존 한국어 모드 문자열을 받는 호환 경로도 유지합니다.

## 개별 표기 비교 옵션

화면은 네 옵션을 각각 선택하고 명시적인 boolean으로 전달합니다. 새 세션에서는 모두 켜짐입니다. 기존 세션에 묶음 옵션이 있으면 괄호·공백·기호 설정의 초기값으로 한 번 옮기고, 영문 대소문자 무시는 기존 동작대로 켭니다. 선택은 해당 사용자의 세션에만 적용되며 공통 DB 설정을 변경하지 않습니다.

| 화면 옵션 | 켜짐 | 꺼짐 |
|---|---|---|
| 등록 키워드의 괄호 설명 제외 | 안티에이징(anti-aging)을 안티에이징으로 준비해 검색 | 원래 괄호 포함 등록명을 비교 대상으로 사용 |
| 띄어쓰기·줄바꿈 차이 허용 | 피부 보습, 피부보습, 피부와 보습 사이 줄바꿈을 같은 표현으로 비교 | 공백과 줄바꿈을 유지해 비교 |
| 영문 대소문자 무시 | Spot과 spot을 같은 표현으로 비교 | 영문 대소문자 구분 |
| 설정된 기호를 공백으로 처리 | 피부&보습을 피부 보습으로 비교 | 공통 기호 목록을 적용하지 않음 |

기호 치환과 공백 정규화는 독립 단계입니다. 예를 들어 피부&보습과 피부보습을 연결해 비교하려면 두 옵션을 모두 켜야 합니다. 괄호 제외는 원문의 괄호를 지우는 설정이 아닙니다. 괄호 제거로 생기는 공백도 공백 옵션을 끄면 그대로 비교합니다.

API와 직접 엔진 호출에서 개별 옵션을 모두 생략하거나 null로 주면 기존 알고리즘을 사용합니다. 하나 이상 명시하면 개별 옵션 경로로 처리합니다. 생략한 항목은 기존 묶음 값과 모드에서 유도합니다. 괄호·공백은 exact에서 exact_relaxed, similar/partial에서 true, 대소문자 무시는 true, 기호 처리는 exact_relaxed가 기본입니다. 일관된 결과를 비교하려면 네 값을 모두 명시합니다. 개별 false는 묶음 true보다 우선합니다.

## 처리 순서

```text
원문과 원장 → 카테고리·리스크 사전 필터 → 설정 스냅샷 → 기호 및 공백 정규화와 위치 맵
           → 키워드별 후보 생성 → 모드별 검출
           → 같은 키워드의 중복·포함 구간 정리 → 원문 위치 정렬
           → 결과 표시와 선택적 집계 (화면에서만 겹친 하이라이트 합침)
```

원장 DataFrame은 엔진에서 복사합니다. 필수 컬럼이 없으면 보충하고 빈 키워드 행을 제외합니다. 기본 컬럼 이외의 추가 데이터는 저장소에서 보존하되 Match2 응답에는 필요한 필드만 담습니다.

| 단계 | 담당 함수 |
|---|---|
| 옵션 호환과 설정 확정 | _resolve_config |
| 원문 비교 준비와 위치 맵 | _prepare_text |
| 개별 옵션 정규화와 원문 위치 복원 | _comparison_with_map, _configured_spans |
| 원장 행과 키워드 후보 준비 | _keyword_records, _keyword_variants |
| 현재 화면의 세 선택지 검출 | _match_exact, _match_fragments (일부 일치와 글자 수 매칭이 공유) |
| 같은 키워드의 중복·포함 구간 정리 | _maximal_matches |
| 기존 호환 호출 | _match_similar, _match_partial, _resolve_exact_overlaps |
| 원문 위치 정렬 | find_matches |

개별 옵션 경로에서는 다른 코드의 겹친 결과를 제거하거나 그 구간을 확장하지 않습니다. 같은 키워드의 중복과 더 긴 구간 안에 포함된 짧은 조각만 정리합니다. 반복 출현과 서로 일부만 겹치는 별도 출현은 유지합니다. 개별 옵션 없는 호환 호출은 기존 모드별 겹침 정책과 긴 문구 재시도를 유지하되 카테고리·리스크 필터는 모든 경로에서 먼저 적용합니다.

## 정확 일치 모드

등록 문자열과 허용 후보를 개별 옵션으로 정규화한 뒤 문장 내부의 일치 구간을 찾습니다. 정규화 위치는 원문 위치로 복원합니다. 정확 모드도 원문 전체가 등록 문자열과 완전히 같은지 비교하는 연산은 아니며 단어 내부의 표현도 찾습니다.

strip_bracket_notes를 끄면 비교 표현은 괄호를 포함한 등록명입니다. 켜면 괄호 설명을 제외한 표현으로 준비합니다. 이 준비 단계는 새 완전 일치와 일부 일치가 공유합니다. 괄호 안의 영문만을 독립 별칭으로 추가하는 설정이 아닙니다. 두 방식 모두 조사·어미 허용 목록은 사용하지 않습니다. 완전 일치는 문장이나 단어의 첫머리에서 시작할 필요가 없으며 준비한 표현 전체가 연속해서 포함되면 검출합니다.

예시로 등록 안티에이징은 새로운 안티에이징으로 관리한다에서 O, 에이징 관리가 필요하다에서 X입니다. 등록 피부는 피부과에서도 O입니다. 등록 피부와 피부보습이 동시에 있으면 두 코드를 모두 보존합니다. 같은 키워드가 피부피부처럼 반복되면 앞·뒤 두 위치를 모두 유지합니다.

개별 옵션 없는 호환 호출은 기존 exact_relaxed 값에 따라 기호 연결 비교·유연한 공백·정규화 비교·문자열 검색과 긴 문구 토큰 재시도를 수행하며 긴 키워드 우선 겹침 정책을 유지합니다. 개별 옵션 호출은 이 재시도를 사용하지 않아 꺼진 공백·괄호 조건을 우회하지 않습니다.

## 기존 유사 키워드 포함 모드 — API 호환용

원문을 영문 숫자 토큰과 한글 토큰으로 나누고 위치를 유지합니다. 키워드 구분자 분리, 괄호 안팎 문자열과 공백 변형을 후보로 사용합니다. 조사 어미 허용 목록, 일부 영어 굴절형과 토큰 단위 비교 및 역매칭 옵션을 적용합니다.

이 모드는 벡터 임베딩이나 의미 유사도 점수를 계산하지 않습니다. 유사라는 이름은 코드에 정의한 표기와 토큰 규칙을 뜻합니다. 단어의 앞부분을 무조건 잘라 후보를 만드는 방식은 제한하며 짧은 변형 후보를 배제하는 규칙이 있습니다.

조사·어미 허용 목록은 이 모드에서만 참조합니다. `으로`, `로`, `에는`은 기본 목록에 포함됩니다. 다만 길이 2 이상인 한글 키워드의 앞뒤에 순수 한글 1~6자가 붙는 경우를 허용하는 합성어 규칙도 별도로 적용하므로, 허용 목록이 모든 검출의 필수 조건은 아닙니다.

개별 옵션 경로에서는 괄호 설명 제외를 끄면 괄호 포함 등록명의 문자열을 요구하고, 켜면 괄호 안팎 후보를 허용합니다. 후보의 토큰 사이 구분자도 선택된 공백·기호 옵션으로 검증합니다. 영문 굴절형·합성어·역매칭에서도 대소문자 선택을 따릅니다. 역매칭과 합성어는 원래 단어 일부를 허용하는 별도 규칙이며 표기 비교 옵션이 이를 단어 전체 검사로 바꾸지는 않습니다. 개별 옵션 없는 기존 유사 모드는 묶음 옵션과 별개로 괄호·공백 변형을 허용하던 동작을 유지합니다.

개별 옵션 없는 기존 호환 호출은 대표 구간을 확장하는 겹침 정책을 유지합니다. 개별 옵션을 명시한 호출은 실제 구간을 키워드별로 보존하며 한 토큰에 여러 직접 일치 위치가 있어도 덮어쓰지 않습니다. 기호 처리를 끄면 토큰 사이뿐 아니라 앞뒤 기호도 비교합니다. 앞 단어만 영문 굴절형인 경우에도 뒤의 일치 단어까지 올바른 범위를 유지합니다. 이 모드는 현재 화면에서 선택하지 않습니다.

## 안티에이징으로 누락 사례와 설계 검토

확인한 원장 B245의 등록명은 `안티에이징(anti-aging)`입니다. 원문 `이제 깊이가 다른 안티에이징으로 지워냅니다.`를 대상으로 다음 기존 묶음 옵션의 동작을 재현했습니다. 아래 검출 여부는 해당 항목이 결과 필터에서 제외되지 않는 조건입니다.

| 등록명 | 검사 방식 | exact_relaxed | 결과 |
|---|---|---|---|
| 안티에이징(anti-aging) | exact | false | 미검출: 괄호 포함 등록명과 원문이 다름 |
| 안티에이징(anti-aging) | exact | true | 안티에이징 구간 검출 |
| 안티에이징(anti-aging) | similar | false | 안티에이징 구간 검출 |
| 안티에이징 | exact | false | 안티에이징 구간 검출: 뒤의 으로는 검사하지 않음 |

따라서 이 사례는 접미사 누락이 아니라 등록명 후보와 옵션의 조합에서 발생합니다. 새 화면에서는 다른 옵션과 무관하게 `등록 키워드의 괄호 설명 제외`만 켜도 해당 구간을 찾습니다. 규칙 요약에는 정확·부분 모드에서 조사·어미 목록을 사용하지 않는다고 표시합니다. DB 변경은 필요하지 않습니다.

표기 차이 설정 분리와 세 선택지의 실행 연결을 구현했습니다. 완전 일치는 문장 내부의 등록 표현 전체, 일부 일치는 문장 내부의 임의의 연속된 2글자 이상 조각으로 정의했습니다. 글자 수 매칭은 최소 길이를 조절합니다. 표시명과 명시적 별칭 관리는 후속 제안입니다.

| 구분 | 권장 설계 | 필요한 검증 |
|---|---|---|
| 검색할 표현 | 표시용 등록명과 명시적 검색 표현을 분리. 예: B245에 안티에이징과 anti-aging을 각각 검수해 등록 | 괄호가 설명인지 필수 문구인지, 영문 동의어 포함 여부 |
| 표기 차이 처리 | 괄호·공백·대소문자·기호를 각각 선택하도록 구현 | 16개 조합과 단일 옵션·원문 위치·호환 호출 검증 |
| 매칭 범위 | 완전 일치는 전체 표현, 일부 일치는 앞·중간·뒷부분의 연속 글자 | 문장 내부 위치, 최소 길이, 반복과 겹친 키워드 보존 |

단어 경계를 강제하는 검사나 의미 기반 AI 검사로 해석하지 않습니다. 선택 옵션과 실제 일치 구간이 결과를 결정합니다. 결과에 적용 규칙과 설정 스냅샷을 저장하는 것은 후속 개선 항목입니다.

## 일부 일치와 글자 수 매칭 — 공통 부분 문자열 엔진

키워드 내부에서 최소 길이 이상의 연속된 부분 문자열을 만들어 문장 어디서든 찾습니다. 키워드의 첫 글자부터 일치할 필요가 없습니다. 화면 일부 일치의 최소 길이는 2로 고정하고 글자 수 매칭은 2~20, API partial은 2~30입니다. 예를 들어 안티에이징 등록 시 에이징 관리가 필요하다는 일부 일치 O, 글자 수 매칭 최소 3글자 O, 최소 4글자 X입니다. 한 단어·문장 여부에 따른 별도 역매칭 옵션은 사용하지 않습니다.

새 개별 옵션 경로는 완전 일치와 같은 표현 준비·정규화를 거쳐 부분 문자열을 비교하고 원문 위치로 복원합니다. 괄호 설명 제외를 켜면 부분 후보를 만들기 전에 괄호 설명을 제외합니다. 끄더라도 원래 등록명의 일부를 찾는 검사이므로 안티에이징(anti-aging)에서 안티에이징만 검출될 수 있습니다. 대소문자 구분 시 Spot과 spot은 전체가 일치하지 않아도 소문자 pot 조각이 최소 길이를 만족하면 일부 일치가 될 수 있습니다.

중복된 부분 문자열은 한 번만 찾고, 원문 시작 위치마다 가장 긴 끝 위치를 보관합니다. 이어서 같은 키워드의 더 긴 구간 안에 포함된 후보를 제거합니다. 따라서 피부보습 하나가 통째로 일치하면 피부·부보·보습 등 여섯 조각 대신 전체 구간 하나만 남습니다. 다른 키워드 코드와 반복 위치는 제거하지 않으며 ababa에서 aba 두 번처럼 서로 겹치는 별도 출현도 유지합니다. 개별 옵션 없는 API 호출은 기존 부분 후보 반환 정책을 유지합니다.

길이가 L인 문자열의 부분 후보 수는 최소 길이를 고정했을 때 대략 L의 제곱에 비례할 수 있습니다. 이 때문에 전체 처리 시간이 단순 원문 글자수에만 비례한다고 가정하지 않습니다. 긴 문서와 이 모드 조합은 별도 성능 검수가 필요합니다.

## 정규화와 위치 복원

기호를 공백으로 바꾸는 단계에서는 원문 길이를 보존합니다. 개별 공백 옵션을 켜면 공백·탭·줄바꿈·NBSP·zero width space·BOM을 비교 문자열에서 제외하고 원문 위치 맵을 유지합니다. 끄면 이 문자를 그대로 비교합니다. 영문 대소문자는 선택에 따라 lower를 적용하며 길이가 늘어나는 변환에도 각 출력 글자를 원문 위치로 매핑합니다. 기존 호환 경로의 공백 정규화와 casefold 처리도 별도로 유지합니다.

영문 비교에 lower 또는 casefold를 사용하는 경로가 혼재합니다. Unicode 전체의 모든 대소문자 확장과 문장 부호 조합을 완벽히 처리한다고 검증된 것은 아닙니다. 특수 Unicode 회귀 사례는 추가 검수 항목입니다.

## 결과와 필터

| Match2 필드 | 의미 |
|---|---|
| term | 원장 키워드 |
| start와 end | 원문 code point 시작과 끝 다음 위치 |
| category | 원장 상품카테고리 |
| risk | 원장 리스크 등급 문자열 |
| detail | 원장 세부 심의기준 |
| kwd_no | 원장 식별 코드 |

결과는 원문 위치 기준으로 정렬합니다. 공통 service.match_text가 카테고리와 리스크를 매칭 전에 필터링합니다. 제외 대상인 긴 키워드가 허용된 짧은 키워드를 가리는 일이 없도록 모든 모드에 이 순서를 적용합니다. 개별 옵션 경로의 실제 결과에는 다른 키워드의 겹친 구간도 남습니다. 화면 highlight_text만 겹치는 구간을 합치고 모든 해당 코드를 함께 표시합니다.

## 화면과 API 어댑터 차이

| 항목 | Streamlit | API |
|---|---|---|
| mode 초기값 | exact | similar |
| 개별 옵션 초기값 | 네 옵션 모두 true | 네 옵션 모두 null이면 기존 호환 경로 |
| 기존 exact_relaxed | UI에서 제거, 기존 세션 이관용 | false, 호환용 deprecated 필드 |
| 부분 최소 길이 상한 | 위젯 20 | 요청 검증 30 |
| 검출 없는 분석 기록 | 저장 안 함 | record=true이면 저장 |
| 분석 ID | 성공 분석마다 새 UUID | 호출자가 제공하거나 새 UUID |
| 지문 | 원문만 SHA 256 | ID와 record를 제외한 요청의 정렬 JSON SHA 256 |
| 입력 전체 저장 | 화면 세션 메모리에 보관 | API 요청 처리 중 메모리 |

기본값과 저장 흐름이 같다고 가정하지 않습니다. 결과 비교는 모드, 네 개별 옵션, 부분 길이, 역매칭 설정, 필터와 같은 원장 revision을 맞춰 수행합니다. Streamlit의 별도 명시적 options 스냅샷은 현재 실행 기록에 저장되지 않습니다. API 지문 계산에서는 null인 신규 옵션을 제거해 기존 요청의 재시도 지문을 보존하며, 명시한 값은 지문에 포함합니다.

## 집계 규칙

텍스트의 동일 코드가 여러 위치에서 검출돼도 한 분석의 조회수는 1 증가합니다. 두 원장 코드가 같은 구간에 대응하면 코드별로 각각 1 증가할 수 있습니다. 검출 위치 수, 고유 키워드 수, 누적 조회수와 최근 7일 이벤트 수는 서로 다른 지표입니다.

현재 리스크 등급은 원장 문자열을 그대로 표시합니다. 여러 검출 등급을 하나의 종합 위험 점수로 합산하거나 가장 높은 등급을 최종 판정으로 선택하는 기능은 없습니다.

## 보존할 기존 동작과 검증

`find_matches_nlp`는 호환 래퍼입니다. suffix_suggestions를 내부 find_matches에 전달하지 않는 기존 동작을 유지합니다. 제안 기능을 수정할 때는 별도 회귀 검증이 필요합니다.

기존 분석 경로에서 수집하지 못하던 접미사 후보 제안은 화면에서 제거했습니다. 자동 제안 기능을 새로 구현한 것은 아닙니다.
공통 규칙 편집은 관리자 키워드 관리 화면으로 이동했습니다. 분석 화면에는 검사 방식과 적용 중인 규칙 요약을 제공합니다.
기호 입력은 한 줄에 하나씩 받아 쉼표도 저장합니다. 여러 글자 기호는 저장 전 거절합니다.

커밋 2d17555의 동작을 담은 matching_baseline.json 27개 사례와 비교합니다.
개별 옵션 없는 동일 입력에서 기존 인수 경로와 MatchingConfig 경로가 같은 결과를 내는지 확인하며,
기존 중복 결과도 호환 기준에 포함합니다. 초기 리팩터링 단계에서는 1,431행 원장에 대해 두 원문·세 모드·완화 옵션 두 값의
12개 조합을 이전 엔진과 비교해 일치를 확인한 이력이 있습니다. 이 이력은 현재 개별 옵션 경로의 결과가 이전과 같다는 뜻은 아닙니다.

B245 재현 테스트는 직접 엔진과 공통 서비스 모두에서 기존 완화 옵션 켜기·끄기, 추가 접미사 유무, 괄호 없는 등록명과 괄호 포함 원문을 비교합니다. 개별 옵션 테스트는 16개 조합, 세 모드의 단일 옵션 효과와 대소문자 우회 여부를 확인합니다. 화면 테스트는 괄호 옵션만 변경해 미검출에서 B245 검출로 전환하고, 옵션 변경 시 결과 숨김과 모드 전환 후 선택 유지까지 확인합니다. API 테스트는 16개 조합, 신규 boolean 검증과 기존 지문 호환을 확인합니다. 운영 DB를 변경하는 테스트는 아닙니다.

회귀 검증은 사전 필터, 반복 위치, 다른 코드의 중첩 보존, 앞뒤 기호 OFF, 세 선택지의 실제 화면 실행과 API 실행, 최소 길이 변경 후 결과 무효화, 기존 표·CSV 열 구성 유지를 포함합니다. Kiwi·임베딩 보조 분석 검증을 포함해 현재 전체 테스트는 29개 통과와 실제 초기화 1개 제외이며 모든 가능한 입력 조합을 보장하지는 않습니다. 기존 테스트 범위와 추가 검수 항목은 운영 검증 설계서에서 구분합니다.
